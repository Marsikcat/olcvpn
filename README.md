# olcvpn

Десктопный клиент для [olcRTC](https://github.com/openlibrecommunity/olcrtc) —
туннеля, который прячет трафик внутри видеопотока конференц-сервиса
(Telemost, Jazz, wbstream, Jitsi).

Один исполняемый файл: интерфейс встроен и открывается в собственном окне
приложения. Клиент управляет ядром `olcrtc` и, для системного VPN, `sing-box`.

<!-- скриншот: docs/screenshot.png -->

## Что умеет

* импорт подписки — ссылка, `olcrtc://` URI или PNG с QR-кодом (декодер внутри);
* список серверов подписки, переключение одним кликом;
* два режима: **весь трафик** через TUN или **только прокси** (SOCKS5);
  режим переключается на лету, без переподключения;
* понятный статус вместо логов: «Защищено», «Восстановление», «Сервер не
  отвечает» — с пингом и точкой выхода (город, страна, IP);
* автоопределение ядра: у `olcrtc` две несовместимые линейки CLI — старая
  флаговая (`-carrier … -id …`) и новая с YAML-конфигом. Клиент опрашивает
  `--help`, распознаёт тип и сам готовит нужный вид конфигурации;
* оформление: тёмная тема, светлая или «как в системе»;
* автозапуск при входе в Windows и автоподключение;
* значок в трее с открытием по двойному клику, работа в фоне, запуск сразу
  свёрнутым;
* обновление из самого приложения: проверка релизов на GitHub, скачивание
  и подмена файлов с перезапуском;
* журнал ядра с фильтрацией шума pion и подсветкой.

## Окно

Интерфейс рисует WebView2 — тот же движок, что в Edge; в Windows 11 он
предустановлен, в Windows 10 ставится вместе с Edge. Отдельного браузера не
открывается, адресной строки нет, окно своё, с иконкой и в Alt-Tab.

Если WebView2 в системе нет, клиент сам откатится на браузер. Принудительно
тот же режим включается флагом:

    olcvpn.exe --browser

Окно прячется в трей: двойной клик по значку открывает его обратно, правая
кнопка даёт меню «Открыть», «Подключить/Отключить» и «Выход». Кнопка
«закрыть» по умолчанию сворачивает туда же, а не завершает приложение —
это переключается в настройках.

Двойной клик распознаётся вручную: systray передаёт только одиночные нажатия,
поэтому два тапа подряд считаются двойным кликом по системному интервалу
(`GetDoubleClickTime`), а не по своей константе.

Иконка собирается из `assets/logo.jpg`: `tools/mklogo` вырезает квадрат,
усредняет по площади до каждого размера, скругляет углы и пишет `olcvpn.ico`
и `web/logo.png` для шапки. Дальше `rsrc` кладёт иконку в
`rsrc_windows_amd64.syso`. Пересобрать:

    go run ./tools/mklogo -src assets/logo.jpg -ico olcvpn.ico -png web/logo.png
    go run github.com/akavel/rsrc@latest -ico olcvpn.ico -arch amd64 -o rsrc_windows_amd64.syso

## Автозапуск

Включается в настройках. Если приложение запущено с правами администратора,
создаётся задача планировщика с «наивысшими правами» — тогда после входа в
систему доступен режим «Весь трафик». Без прав используется ключ реестра
`Run`, и автозапуск поднимется только в режиме «Только прокси»: TUN без
администратора не встаёт.

## Обновления

Раздел «Дополнительно» показывает текущую версию и умеет проверить релизы
GitHub. Если есть свежее, появляется кнопка «Обновить»: клиент качает архив,
распаковывает его в `update/` и передаёт подмену маленькому скрипту.

Скрипт нужен потому, что запущенный exe не может переписать сам себя: он ждёт,
пока процесс исчезнет, копирует файлы поверх, стартует новую сборку и удаляет
себя. Настройки при этом не трогаются — `olcvpn.json` в архив не входит.

Проверка идёт при каждом запуске. Если сети нет — например, машина только
загрузилась, — проверка откладывается до первого успешного подключения:
на закрытом канале туннель может быть единственным выходом наружу.

Запросы обновления не используют системный прокси. Оговорка: в режиме «весь
трафик» они всё равно идут через TUN — это маршрут уровня системы, обойти его
из приложения нельзя.

## Сборка

Нужен Go 1.26+.

    go build -ldflags="-H windowsgui -s -w -X main.version=v0.1.3" -o olcvpn.exe .

Без `-X main.version` сборка считается версией `dev` и всегда предлагает
обновиться до последнего релиза.

Без `-H windowsgui` рядом с окном будет висеть консоль.

## Что положить рядом

Бинарники ядра и sing-box в репозиторий не входят — соберите или скачайте сами:

    olcvpn.exe
    bin/olcrtc.exe       ядро olcRTC (любая линейка, тип определится сам)
    bin/sing-box.exe     sing-box 1.12+ — только для режима «весь трафик»

Клиент ищет `olcrtc*.exe` в `bin/` и рядом с собой, так что можно держать
несколько сборок ядра и переключаться между ними в разделе «Дополнительно».

Ядро, которое кладётся в релиз, собирается из
[OlConnect_manager](https://github.com/Oleglog/OlConnect_manager) с патчем из
`patches/`:

    git -C OlConnect_manager checkout server-v2.3.5
    git -C OlConnect_manager apply ../olcvpn/patches/olcrtc-reorder-hold.patch
    cd OlConnect_manager && go build -trimpath -o ../olcvpn/bin/olcrtc-fork.exe ./cmd/olcrtc

**Важно:** сборка клиента должна совпадать по протоколу с тем, что запущено на
сервере. Линейки ядра между собой несовместимы на уровне wire-формата: клиент
входит в комнату, видит видеопоток, но не может разобрать кадры и висит на
`wait for peer` либо `read welcome: timeout`. Если так — берите ядро из того же
репозитория и примерно того же коммита, что и сервер.

## Известные ограничения

Это свойства ядра `server-v2.3.5`, а не клиента, но знать их полезно.

* **Нужен патч на обеих сторонах.** С октября Телемост оставляет дыры в
  нумерации RTP-пакетов, и ядро без `patches/olcrtc-reorder-hold.patch`
  встаёт на каждой из них примерно на 25 секунд. Тогда клиент видит сервер, но
  висит на `read welcome: timeout`. Чтобы заработало, патч нужен и в клиенте
  (он есть в релизе), и на сервере.
* **Один клиент на сервер.** В `vp8channel` этой версии сервер шлёт данные всем
  клиентам комнаты под одной меткой, и при втором клиенте потоки смешиваются:
  `decrypt failed`, пропущенные pong, переподключения. Вторым считается и только
  что отключившийся клиент — сервер держит его сессию ещё ~90 секунд. Не
  подключайтесь к одному серверу с двух устройств одновременно.
* **Скорость.** Через Телемост это 15–40 КБ/с в каждую сторону при задержке
  около секунды. Для мессенджеров и страниц хватает, для видео — нет.

### Настройка сервера для Телемоста: склейка кадров

Телемост теряет 10–20% RTP-пакетов. По умолчанию ядро склеивает до 64 пакетов
KCP в один видеокадр — до 60 КБ, то есть в десятки RTP-пакетов. Такой кадр
доходит, только если дошёл каждый его пакет, поэтому при таких потерях почти
все кадры с данными гибнут, а KCP раз за разом переотправляет целые пачки.

Склейкой управляет только отправитель, а получатель понимает оба вида кадров.
Поэтому olcvpn всегда отправляет без склейки, что бы ни пришло в подписке, а на
сервере это отдельная настройка инстанса:

    OLCRTC_VP8_BATCH=1

Замеры на одном и том же сервере:

| направление | склейка 64 | склейка 1 |
|---|---|---|
| загрузка с сервера | ~5 КБ/с | 17–22 КБ/с |
| выгрузка на сервер | 15–18 КБ/с | 21–42 КБ/с |

## Запуск

    start.cmd     с правами администратора — нужно для режима «весь трафик»
    olcvpn.exe    без прав — доступен только SOCKS5

Интерфейс поднимается на `http://127.0.0.1:8899/` и открывается сам; адрес
дублируется в файле `olcvpn.url`.

## Импорт подписки

В поле импорта принимается любая из форм, в которых панель раздаёт доступ:

    https://host:port/sub/xxxx                       прямая ссылка на список
    olconnect://subscription?url=...&name=...        обёртка вокруг неё
    olconnect://telemost@room/<комната>?key=...      один сервер, полная форма
    olconnect://telemost@r/<комната>?k=...&t=...     один сервер, сжатая (из QR)
    {"type":"olcrtc-sub","u":"https://..."}          JSON из QR-кода

Плюс сам PNG или JPEG с QR-кодом — кнопка «Из QR-файла», декодер встроен.

Схема `olcrtc://` тоже принимается: 12 сентября проект переименовали в
OlConnect, и новые ссылки идут с `olconnect://`, а старые продолжают работать.
Серверы `openflux://` — другой протокол со своей программой; клиент их
пропускает и говорит, сколько пропустил.

Формат разобран по коду самой панели (`internal/admin/api_instances.go` в
OlConnect_manager), и в нём есть две ловушки. Когда транспорт `datachannel`,
панель параметр `transport` просто не пишет — его нельзя заменять своим
умолчанием. А в сжатой форме опущены `fps=60` и `batch=8`. Комната вставляется
как есть, поэтому бывает и номером, и полным адресом `https://…`.

### Обновление и удаление

Клиент держит одну подписку. В разделе «Подписка» видно её имя, адрес панели и
когда список сверяли в последний раз; рядом кнопки «Обновить» и «Удалить».

«Обновить» забирает список заново и показывает, что изменилось: новые,
изменённые и удалённые серверы. Серверы сопоставляются по провайдеру, комнате
и транспорту, так что сервер со сменившимся ключом остаётся выбранным. Если
изменился тот, к которому вы подключены, клиент попросит переподключиться —
сам он рабочее соединение не рвёт. Подписка обновляется и при каждом запуске,
а если панель недоступна, клиент работает по сохранённому списку.

«Удалить» разрывает подключение, стирает серверы и удаляет с диска
сгенерированный конфиг ядра — в нём хранится ключ.

Ссылка на подписку несёт ещё `mirror_url` и `mirror_key`: зашифрованную копию
того же списка на Яндекс.Диске, на случай если панель заблокирована. Клиент
зеркало пока не читает — берётся только основной адрес.

Панели отдают подписку под собственным сертификатом, поэтому она забирается
без проверки CA.

## Режим TUN

`sing-box` поднимает интерфейс `olcvpn-tun` и заворачивает в SOCKS ядра весь
трафик, кроме самих `olcrtc` / `sing-box` / `olcvpn`, приватных подсетей и
доменов, перечисленных в настройках как «мимо туннеля». Домены сигналинга
обязаны идти напрямую, иначе туннель замкнётся на себя.

Не включайте этот режим параллельно с другим VPN-клиентом: два туннеля
подерутся за маршрут по умолчанию.

## Файлы рядом с программой

    olcvpn.json           настройки и импортированные серверы (содержит ключи)
    olcvpn.url            адрес интерфейса
    core-config.yaml      конфиг, сгенерированный для YAML-ядра
    sing-box-config.json  конфиг TUN
    data/                 рабочий каталог ядра

`olcvpn.json` и `core-config.yaml` содержат ключи шифрования вашей подписки —
не выкладывайте их.
