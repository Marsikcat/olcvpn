# olcvpn

Десктопный клиент для [olcRTC](https://github.com/openlibrecommunity/olcrtc) —
туннеля, который прячет трафик внутри видеопотока конференц-сервиса
(Telemost, Jazz, wbstream, Jitsi).

Один исполняемый файл: интерфейс встроен и открывается в браузере.
Клиент управляет ядром `olcrtc` и, для системного VPN, `sing-box`.

## Что умеет

* импорт подписки — ссылка, `olcrtc://` URI или PNG с QR-кодом (декодер внутри);
* список серверов подписки, переключение одним кликом;
* два режима: **весь трафик** через TUN или **только прокси** (SOCKS5);
  режим переключается на лету, без переподключения;
* понятный статус вместо логов: «Защищено», «Восстановление», «Сервер не
  отвечает» — с пингом и точкой выхода (город, страна, IP);
* автоопределение ядра: у `olcrtc` две несовместимые линейки CLI — старая
  флаговая (`-carrier … -id …`) и новая с YAML-конфигом. Клиент опрашивает
  `--help`, распознаёт тип и сам готовит нужный вид конфигурации;
* журнал ядра с фильтрацией шума pion и подсветкой.

## Сборка

Нужен Go 1.26+.

    go build -o olcvpn.exe .

## Что положить рядом

Бинарники ядра и sing-box в репозиторий не входят — соберите или скачайте сами:

    olcvpn.exe
    bin/olcrtc.exe       ядро olcRTC (любая линейка, тип определится сам)
    bin/sing-box.exe     sing-box 1.12+ — только для режима «весь трафик»

Клиент ищет `olcrtc*.exe` в `bin/` и рядом с собой, так что можно держать
несколько сборок ядра и переключаться между ними в разделе «Дополнительно».

Ядро собирается из репозитория olcRTC:

    go build -o bin/olcrtc.exe ./cmd/olcrtc

**Важно:** сборка клиента должна совпадать по протоколу с тем, что запущено на
сервере. Линейки ядра между собой несовместимы на уровне wire-формата: клиент
входит в комнату, видит видеопоток, но не может разобрать кадры и висит на
`wait for peer` либо `read welcome: timeout`. Если так — берите ядро из того же
репозитория и примерно того же коммита, что и сервер.

## Запуск

    start.cmd     с правами администратора — нужно для режима «весь трафик»
    olcvpn.exe    без прав — доступен только SOCKS5

Интерфейс поднимается на `http://127.0.0.1:8899/` и открывается сам; адрес
дублируется в файле `olcvpn.url`.

## Режим TUN

`sing-box` поднимает интерфейс `olcvpn-tun` и заворачивает в SOCKS ядра весь
трафик, кроме самих `olcrtc` / `sing-box` / `olcvpn`, приватных подсетей и
доменов, перечисленных в настройках как «мимо туннеля». Домены сигналинга
обязаны идти напрямую, иначе туннель замкнётся на себя.

Не включайте этот режим параллельно с другим VPN-клиентом: два туннеля
подерутся за маршрут по умолчанию.

## Файлы рядом с программой

    olcvpn.json           настройки и импортированные серверы (содержит ключи)
    olcvpn.url            адрес интерфейса
    core-config.yaml      конфиг, сгенерированный для YAML-ядра
    sing-box-config.json  конфиг TUN
    data/                 рабочий каталог ядра

`olcvpn.json` и `core-config.yaml` содержат ключи шифрования вашей подписки —
не выкладывайте их.
